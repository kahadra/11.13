교재 I · Wooldridge — 에이전트들의 사회

• 에이전트의 두 능력: 자율적 행동 + 협력·조정·교섭 같은 사회적 상호작용 (서문)
• 모두가 같은 목표라는 ‘선의 가정’은 한 주인이 만든 시스템에서나 성립 (8.1)
• 각자 이익을 좇는 사이에서는 효용, 의존, 반복, 약속이 협력을 좌우 (11–15장)

교재 II · Albada — 에이전트를 만드는 방법

• 단일 에이전트로 시작하고, 필요할 때만 나눈다 (8장)
• 조정 방식: 민주적(합의) · 관리자(중앙 통제, 단 단일 장애점이자 병목) · 스웜(분산, 하나가 죽어도 계속)
• 기억과 학습(6–7장), 평가와 감시(9–10장), 장애 대응(10·12장)

이 프로젝트의 위치: 목표가 서로 다른 이기적 에이전트의 사회(교재 I)를 관리자 조정 + 인수인계로 만드는 일(교재 II)

요소 ① 시간과 판

Multi-Agent · 2026.11.13
06:25–07:15 · 00:50

출발점

최초 설계 · 팀 통합본
  • 120사이클 + 실행 1시간 제한 (에이전트는 모름)
  • 판마다 새 데이터베이스 · 새 에이전트
  • 한 명씩 순서대로 호출

실험에서 본 것

  • 30판 모두 12–15사이클에 종료
  • 30판 = 30번의 첫 판, 쌓이는 경험 0

최종 설계

11/6 영속 풀 · 11/8 30사이클
  • 에이전트 16명 영속 풀 (판마다 12명, 참가 횟수 균등)
  • 판은 사이클로만 끝냄 (30사이클)
  • 시간은 멈춤 감지에만 · 호출은 동시에

교재의 이론

  • 다시 만날 가능성(미래의 그림자)이 협력을 합리적으로 만든다 (I 11.5)
  • 단, 횟수가 정해지면 마지막 판의 배신이 예상된다 (역진 귀납)
  • 세션을 넘는 기억이 있어야 학습이 된다 (II 6장)

고민한 지점

  • 시간 제한을 알려 줄까, 없앨까? → 시간은 호출 속도와 장애에 따라 변하는 실행 환경의 값. 결과를 정하게 두면 실험이 오염된다
  • 대가: 판당 약 72분 · 120사이클은 포기하고 30사이클로
바꿔야 했던 이유 — 시간은 규칙이 아니라 실행 환경이었다. 결과를 정하는 변수에서 빼고, 같은 상대를 다시 만나게 해야 학습이 가능했다
